# ADR-0009: A second local model for planning (Qwen)

- **Status**: Accepted 2026-10-02 (D15). Supersedes the planner clause of ADR-0008. Links: D15, I3, I4, I5, [02 §14](../02-architecture.md), ADR-0008.
- **Context**: Shoppers write in English, Chinese and Cantonese, and a mandate is a sentence. Laya answers typed questions over structured options; it misread Chinese probes [F26] and does not fill fields from free text. The earlier decline of a local generative planner is lifted [F27].
- **Decision**: Qwen3.5-9B (4B selectable), Q4_K_M GGUF on llama.cpp `llama-server`, 127.0.0.1 only, files pinned by commit and SHA-256 [F27, F63]. `PLANNER_PROVIDER=local` returns one grammar-constrained JSON answer whose enums come from the supplied catalogue; code clamps quantity, guards near-ties and returns no proposal on any failure [F58]. The same server backs a sentence-to-rules compiler: the model fills typed fields, code computes money and dates, the shopper confirms, and the rule-based compile is the fallback [F60]. Qwen never gates a decision and is never the judge; Laya stays the judge.
- **Consequences**: Two model services to start and explain, and more memory on the booth Mac [F27]. Planner and judge no longer share a model. Measured on 25 calls over author-written requests: the 9B proposed a wrong item in 0 of 26 scenarios, p50 1,735 ms; no held-out set, and the Chinese and Cantonese cases are few [F68]. Listing text can move it (2 of 31 injected listings changed the proposal in a test), so by default it is not shown descriptions (I4).
- **Rejected alternatives**: Qwen as a second judge (no calibrated probabilities, so no typed gate for I3); the 4B as default (a lower correct rate in the same run [F68]); a hosted planner (key, network, listing text leaves the Mac).
