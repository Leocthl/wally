# ADR-0006: TypeScript pnpm monorepo, model servers as local services

- **Status**: Accepted (revised 2026-10-02, contract V2). Links: 00-context lanes, [02 §13](../02-architecture.md), ADR-0008, ADR-0009.
- **Context**: A 3-4 person team in 48 h [F13] runs lanes in parallel. Engine, UI and the offline verifier share types and crypto. The judge model ships as a Python package with an HTTP server [F11c]; the planner model runs under llama.cpp [F27].
- **Decision**: One TypeScript pnpm monorepo: `apps/web`, `apps/verifier`, `packages/core`, `packages/rail-sim`, `packages/agent`, `packages/harness`. JSON Schema is the source of truth, with generated types and ajv at boundaries. Append-only JSONL, no database. Laya runs as a pinned local Python service in `services/laya/` and Qwen as a pinned `llama-server` in `services/qwen/` (setup, serve, stop, smoke each), both reached over HTTP on 127.0.0.1 only. Schema validators are compiled ahead of time, so no page needs `eval`.
- **Consequences**: One language for our code and one test runner; the verifier reuses core crypto; ports in `core` keep lanes independent. The model services stay outside the packages, pinned by version or commit and weights hash; CI mocks them.
- **Rejected alternative**: Python (FastAPI) backend with a React frontend. Better data tooling for the harness, but two type systems and a second crypto implementation for the browser verifier.
