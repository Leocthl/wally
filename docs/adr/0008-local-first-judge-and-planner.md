# ADR-0008: Local-first judge on Laya; planner clause superseded by ADR-0009

- **Status**: Accepted 2026-10-02 (contract V2 as amended). The judge decision stands. The planner decision (Laya is the only model) is superseded by D15 and ADR-0009. Links: D5, D12, D15, I4, I5, [02 §9 and §14](../02-architecture.md), ADR-0001.
- **Context**: The booth demo must run with no network and no API key [F14]; hosted judge access is waitlisted [F11b]. Laya runs locally under Apache-2.0 and answers typed questions with probabilities [F11c]; measured latency on this Mac fits the judge timeout [F26, F34]. Laya cannot read raw pages, do arithmetic or write text.
- **Decision**: Laya is the judge: typed questions, probabilities, rotation-averaged. The first planner was a Laya decision loop inside a deterministic harness: item, variant and next action, abstaining on a small margin, under a step cap. It remains the `rule` provider, the default. Listings arrive structured; arithmetic, cart building and all wording are code and templates. `replay` backs both for CI and the booth.
- **Consequences**: No vendor, no key, no data leaving the Mac. While Laya was the only model, planner and judge shared it and their errors could correlate; ADR-0009 adds a planner model for requests Laya cannot read. The engine rules and the rail limit stay model-free. "Why this item" is answered from the logged planner trace (E4).
- **Rejected alternatives (then)**: a second, generative local model for the planner (dropped on 2026-10-02, taken up again in ADR-0009); a hosted Claude planner (needs a key and a network; the `claude` provider is now removed).
